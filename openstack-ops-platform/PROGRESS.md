# OpenStack 운영 지원 플랫폼 진행사항

> OpenStack 환경에서 엔지니어가 일일점검, 모니터링, 장애 확인 및 운영 업무를 편리하게 수행할 수 있도록 지원하는 플랫폼의 진행 기록입니다.

## 프로젝트 개요

- 프로젝트명: OpenStack 운영 지원 플랫폼 (가칭)
- 시작일: 2026-08-21
- 현재 단계: 대시보드 UI 프로토타입 구현
- 대상 사용자: OpenStack 운영 엔지니어 및 관리자
- 문서 상태: 초기 생성

## 추진 목표

- 반복되는 일일점검 업무를 자동화한다.
- OpenStack 서비스와 인프라 상태를 한 화면에서 확인할 수 있게 한다.
- 이상 징후와 장애를 빠르게 발견하고 대응할 수 있게 한다.
- 점검 결과와 장애 이력을 누적하여 추적 가능하게 한다.
- 운영 절차를 표준화하고 담당자별 업무 편차를 줄인다.

## 예상 기능 범위

### 일일점검

- OpenStack 주요 서비스 상태 확인
- 컨트롤러, 컴퓨트, 네트워크, 스토리지 노드 상태 확인
- 하이퍼바이저 및 리소스 사용량 확인
- 인스턴스, 볼륨, 네트워크 등 주요 자원 이상 여부 확인
- 점검 결과 저장 및 일일 보고서 생성

### 모니터링

- CPU, 메모리, 디스크, 네트워크 사용량 시각화
- OpenStack API 및 서비스 상태 모니터링
- 임계치 기반 경고와 장애 알림
- 현재 장애 및 과거 이력 조회

### 운영 지원

- 자주 사용하는 운영 명령과 절차 제공
- 장애 대응용 진단 정보 수집
- 작업 및 변경 이력 기록
- 사용자 권한에 따른 기능 제어

### 공급자 연결

- OpenStack 환경의 대표 VIP 등록
- VIP 대상 SSH 연결
- VIP가 연결한 활성 Controller의 호스트명 확인
- 연결된 Controller를 기준으로 OpenStack 환경 및 노드 구성 확인
- 각 노드의 CPU, 메모리, 디스크, 네트워크 자원 상태 수집
- Controller, Compute, Network, Storage 서비스 상태 수집
- 등록된 공급자를 대상으로 일일점검 실행
- 공급자 저장 전 SSH 연결과 수집 가능 항목 확인
- SSH 비밀번호와 개인키를 화면이나 로그에 노출하지 않음

### 공급자 기반 수집 구조

1. 대표 VIP를 통해 활성 Controller에 SSH 연결
2. OpenStack 배포 방식과 사용 가능한 관리 도구 확인
3. Controller에서 노드 및 서비스 목록 수집
4. 접근 가능한 방식에 따라 노드별 자원 상태 수집
5. 수집 결과를 표준 형식으로 변환하여 대시보드에 표시
6. 동일한 수집기를 일일점검 작업에서 재사용

수집 방식은 환경별로 다음 순서로 결정한다.

- 기존 Prometheus 또는 모니터링 시스템이 있으면 해당 메트릭 사용
- OpenStack API/CLI로 하이퍼바이저, 서비스 및 에이전트 상태 확인
- Controller를 점프 호스트로 사용해 각 노드에 SSH 점검
- 배포 방식에 따라 systemd, 컨테이너, Pacemaker/HAProxy 상태 확인

### SSH 및 권한 모델

- 플랫폼은 컨테이너 또는 별도 배포 서버에서 실행한다.
- 플랫폼 실행 위치에서 모든 Controller 및 Compute 노드로 직접 SSH 접속할 수 있다.
- root 로그인을 전제로 하지 않고 sudo 권한이 있는 운영 계정을 사용한다.
- 읽기 전용 점검 명령은 일반 권한으로 실행하고 필요한 명령만 제한적으로 sudo를 사용한다.
- 공급자 연결 시 passwordless sudo 여부와 사용 가능한 관리 도구를 자동 탐지한다.
- 운영 적용 시 점검 명령 전용 sudoers 정책을 제공한다.

## 결정사항

- 진행사항은 이 문서에 지속적으로 누적한다.
- 세부 기술 스택은 운영 환경과 요구사항을 확인한 후 결정한다.
- 전체 화면은 OKESTRO의 상징색인 어두운 남색을 중심으로 디자인한다.
- 경고, 장애, 정상 상태가 명확히 구분되도록 상태 색상은 기본 테마와 별도로 정의한다.

## 확인이 필요한 사항

- OpenStack 배포판과 버전
- 현재 사용 중인 모니터링 도구 및 수집 데이터
- 실제 일일점검 체크리스트
- 플랫폼 사용자와 필요한 권한 체계
- 장애 알림을 받을 채널
- 구축 대상 서버와 네트워크 접근 조건
- 최종 배포 대상 사이트의 업로드 규격과 실행 환경
- 대상 사이트의 컨테이너 이미지 반입 및 레지스트리 사용 가능 여부
- SSH 사용자명, 포트 및 호스트 키 검증 정책
- Keystone API 포트와 TLS 인증서 검증 정책
- OpenStack 배포 방식(Kolla-Ansible, 패키지, TripleO 등)
- 기존 Prometheus, Grafana 또는 Node Exporter 구성 여부
- Controller에서 사용할 수 있는 OpenRC 또는 clouds.yaml 위치
- 일일점검에서 확인할 필수 서비스와 장애 판정 기준
- 기존 자동화 도구 또는 운영 스크립트의 재사용 가능 여부
- OKESTRO 공식 브랜드 색상 코드 및 디자인 가이드
- 기본색, 보조색, 강조색과 정상·주의·위험 상태 색상
