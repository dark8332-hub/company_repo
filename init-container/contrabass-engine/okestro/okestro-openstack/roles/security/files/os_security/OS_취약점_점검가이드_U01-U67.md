## U-01. root 계정 원격 접속 제한

####현재 구현되어있는 cephadm 로직 상 root계정 필요. 따라서 관리자가 수동으로 판단하여 적용 필요

### 점검 내용

시스템 정책에 root 계정의 원격터미널 접속 차단 설정이 적용 여부 점검

### 조치 방법

원격 접속 시 root 계정으로 접속할 수 없도록 파일 내용 설정

### 확인 방법

[Ubuntu/Debian - SSH]
Step 1) /etc/ssh/sshd_config 파일에서 PermitRootLogin 값 확인
```bash
# grep -i PermitRootLogin /etc/ssh/sshd_config | grep -v '#'
```
Step 2) PermitRootLogin yes 인 경우 no 로 변경
```bash
# sed -i '/PermitRootLogin/ s/yes/no/g' /etc/ssh/sshd_config
# systemctl restart ssh
```

## U-02. 패스워드 복잡성 설정

### 점검 내용

비밀번호 관리 정책 설정 여부 점검

### 조치 방법

root 계정을 포함한 사용자 계정의 비밀번호를 영문, 숫자, 특수문자를 포함하여 최소 8자리 이상 및
최소 사용 기간 1일, 최대 사용 기간 90일, 최근 비밀번호 기억 4회 이상으로 설정

### 확인 방법

[Ubuntu/Debian - Debian 계열]
Step 1) /etc/security/pwquality.conf 파일에 비밀번호 복잡도 설정
```bash
# vi /etc/security/pwquality.conf
```
minlen = 8
dcredit = -1
ucredit = -1
lcredit = -1
ocredit = -1
enforce_for_root
Step 2) /etc/pam.d/common-password 파일에서 pam_pwquality.so 순서 확인 및 pam_pwhistory.so remember=4 설정
```bash
# cat /etc/pam.d/common-password | grep -E 'pam_pwquality|pam_unix|pam_pwhistory'
```
※ pam_pwquality.so, pam_pwhistory.so 모듈은 pam_unix.so 모듈 위에 위치해야 함
Step 3) /etc/login.defs 파일에서 비밀번호 유효기간 설정
```bash
# grep -E 'PASS_MAX_DAYS|PASS_MIN_DAYS' /etc/login.defs
```
PASS_MAX_DAYS 90
PASS_MIN_DAYS 1

## U-03. 계정 잠금 임계값 설정

### 점검 내용

사용자 계정 로그인 실패 시 계정 잠금 임계값이 설정 여부 점검

### 조치 방법

계정 잠금 임계값을 10회 이하로 설정

### 확인 방법

[Ubuntu/Debian - pam_faillock]
Step 1) /etc/pam.d/common-auth 파일에 pam_faillock.so 설정 확인
```bash
# grep pam_faillock /etc/pam.d/common-auth
```
auth required pam_faillock.so preauth audit deny=10 unlock_time=120
Step 2) /etc/pam.d/common-account 파일에 pam_faillock.so 설정 확인
```bash
# grep pam_faillock /etc/pam.d/common-account
```
account required pam_faillock.so
※ deny=10 : 10회 이상 실패 시 계정 잠금
※ unlock_time=120 : 120초 후 자동 잠금 해제

## U-04. 패스워드 파일 보호

### 점검 내용

시스템의 사용자 계정(root, 일반 사용자) 정보가 저장된 파일(/etc/passwd, /etc/shadow 등)에
사용자 계정 비밀번호가 암호화 저장 여부 점검

### 조치 방법

비밀번호 암호화 저장·관리 설정

### 확인 방법

[Ubuntu/Debian]
Step 1) /etc/passwd 파일에서 두 번째 필드가 x 인지 확인 (shadow 사용 여부)
```bash
# awk -F: '{print $1":"$2}' /etc/passwd | grep -v ':x$'
```
※ 두 번째 필드가 x 이면 /etc/shadow 에 암호화 저장 → 양호
Step 2) x 가 아닌 계정이 있으면 pwconv 명령으로 shadow 비밀번호 적용
```bash
# pwconv
```

## U-05. root 이외 UID 0 금지

### 점검 내용

사용자 계정 정보가 저장된 파일(/etc/passwd, /etc/shadow 등)에 root(UID=0) 계정과 동일한
UID를 가진 계정이 존재 여부 점검

### 조치 방법

Ÿ UID가 0으로 설정된 계정을 0 이외의 중복되지 않은 UID로 변경 또는 불필요한 계정인 경우
제거하도록 설정
Ÿ (사용 중인 계정인 경우 명령어를 통한 조치가 적용되지 않을 수 있으므로 /etc/passwd 파일을 통해
변경)

### 확인 방법

[Ubuntu/Debian]
Step 1) /etc/passwd 파일에서 root 이외 UID=0 계정 확인
```bash
# awk -F: '{print $1":"$3}' /etc/passwd | grep -v '^root:' | grep ':0$'
```
Step 2) UID=0 발견 시 usermod 명령으로 변경 또는 불필요한 경우 제거
```bash
# usermod -u <변경할 UID> <사용자 이름>
```

## U-06. su 명령어 제한

### 점검 내용

su 명령어 사용을 허용하는 사용자를 지정한 그룹이 설정 여부 점검

### 조치 방법

PAM 모듈 설정 또는 su 명령어 허용 그룹 생성 후 su 명령어 일반 사용자 권한 제거하도록 설정

### 확인 방법

[Ubuntu/Debian - PAM 모듈 이용]
Step 1) /etc/group 에서 wheel 그룹 확인
```bash
# grep wheel /etc/group
```
Step 2) wheel 그룹이 없으면 생성 후 허용 계정 등록
```bash
# groupadd wheel
# usermod -aG wheel <허용할 계정>
```
Step 3) /etc/pam.d/su 파일에 pam_wheel.so 설정
```bash
# grep pam_wheel /etc/pam.d/su
```
auth required pam_wheel.so group=wheel

## U-07. 불필요한 계정 제거

### 점검 내용

시스템 계정 중 불필요한 계정(퇴직, 전직, 휴직 등의 이유로 사용하지 않는 계정 및 장기적으로 사용하지
않는 계정 등)이 존재 여부 점검

### 조치 방법

시스템에 존재하는 계정 확인 후 불필요한 계정 제거하도록 설정

### 확인 방법

[Ubuntu/Debian]
Step 1) /etc/passwd 에서 불필요한 기본 계정 확인 (adm, lp, sync, shutdown, halt, news, uucp, operator, games, gopher 등)
```bash
# awk -F: '{print $1}' /etc/passwd | grep -E '^(adm|lp|sync|shutdown|halt|news|uucp|operator|games|gopher)$'
```
Step 2) 불필요한 계정 제거
```bash
# userdel <사용자 이름>
```
※ /etc/passwd 파일에서 계정 앞에 # 삽입은 주석 처리가 되지 않으므로 반드시 userdel 명령 사용

## U-08. 관리자 그룹 최소화

### 점검 내용

시스템 관리자 그룹에 최소한(root 계정과 시스템 관리에 허용된 계정)의 계정만 존재 여부 점검

### 조치 방법

관리자 그룹에 등록된 계정 확인 후 불필요한 계정 제거하도록 설정

### 확인 방법

[Ubuntu/Debian]
Step 1) /etc/group 파일에서 root 그룹에 포함된 계정 확인
```bash
# grep '^root:' /etc/group | cut -d: -f4
```
Step 2) 불필요한 계정을 root 그룹에서 제거
```bash
# gpasswd -d <사용자 이름> root
```

불필요한 그룹이 존재하는 경우 관리자와 검토하여 제거하도록 설정
※ /etc/group 파일과 /etc/passwd 파일을 비교하여 점검하기를 권고함

### 확인 방법

[Ubuntu/Debian]
Step 1) /etc/group, /etc/gshadow 파일에서 불필요한 그룹 확인
```bash
# cat /etc/group
# cat /etc/gshadow
```

```bash
# groupdel <그룹 이름>
```
※ 그룹 제거 전 해당 그룹 권한으로 존재하는 파일 여부 확인 필요

## U-10. 동일 UID 금지

### 점검 내용

/etc/passwd 파일 내 UID가 동일한 사용자 계정 존재 여부 점검

### 조치 방법

동일한 UID를 가진 사용자 계정의 UID를 중복되지 않도록 변경하도록 설정

### 확인 방법

[Ubuntu/Debian]
Step 1) /etc/passwd 파일에서 중복 UID 확인
```bash
# awk -F: '{print $1" "$3}' /etc/passwd | sort -k2 | uniq -f1 -D
```
Step 2) 중복 UID 발견 시 usermod 명령으로 변경
```bash
# usermod -u <변경할 UID> <사용자 이름>
```

## U-11. 불필요한 계정 쉘 제한

### 점검 내용

로그인이 불필요한 계정(adm, sys, daemon 등)에 쉘 부여 여부 점검

### 조치 방법

로그인이 필요하지 않은 계정에 대해 /bin/false(/sbin/nologin) 쉘 부여 설정

### 확인 방법

[Ubuntu/Debian]
Step 1) 로그인 불필요 계정(daemon, bin, sys, adm, nobody 등)의 쉘 확인
```bash
# awk -F: '/^(daemon|bin|sys|adm|nobody)/{print $1":"$7}' /etc/passwd
```
Step 2) 로그인 쉘이 /bin/false 또는 /usr/sbin/nologin 이 아닌 경우 변경
```bash
# usermod -s /usr/sbin/nologin <계정명>
```

## U-13. 패스워드 암호화 알고리즘

### 점검 내용

안전한 비밀번호 암호화 알고리즘을 사용 여부 점검

### 조치 방법

SHA-2 이상의 안전한 비밀번호 암호화 알고리즘 적용 설정

### 확인 방법

[Ubuntu/Debian]
Step 1) /etc/login.defs 파일에서 ENCRYPT_METHOD 값 확인
```bash
# grep -i ENCRYPT_METHOD /etc/login.defs | grep -v '^#'
```
ENCRYPT_METHOD SHA512
Step 2) SHA-2 이상이 아닌 경우 변경
```bash
# sed -i 's/^ENCRYPT_METHOD.*/ENCRYPT_METHOD SHA512/' /etc/login.defs
```
Step 3) /etc/pam.d/common-password 파일에서 pam_unix.so 알고리즘 확인
```bash
# grep pam_unix.so /etc/pam.d/common-password | grep -v '^#'
```
password [success=1 default=ignore] pam_unix.so obscure yescrypt
※ SHA-256, SHA-512, yescrypt 중 하나가 설정되어 있으면 양호

## U-14. PATH 환경변수 설정

### 점검 내용

root 계정의 PATH 환경변수에 “.”(마침표)이 포함 여부 점검

### 조치 방법

root 계정의 환경설정 파일(/.profile, /.bashrc 등)과 시스템 환경설정 파일(/etc/profile 등)에 설정된
PATH 환경변수에서 현재 디렉터리를 나타내는 “.”을 PATH 환경변수의 마지막으로 이동하도록 설정
※ /etc/profile 파일, root 계정, 일반 사용자 계정의 환경설정 파일을 순차적으로 검색하여 확인

### 확인 방법

[Ubuntu/Debian]
Step 1) /etc/environment 파일에서 PATH 환경변수 확인
```bash
# cat /etc/environment
# echo $PATH
```
Step 2) PATH 에 . 이 포함된 경우 제거
```bash
# vi /etc/environment
```
※ PATH=값에서 .:, :./, :. 형태의 현재 디렉터리 참조를 제거

## U-15. 소유자 없는 파일 점검

### 점검 내용

소유자가 존재하지 않는 파일 및 디렉터리의 존재 여부 점검

### 조치 방법

소유자가 존재하지 않는 파일 및 디렉터리 제거 또는 소유자 변경 설정

### 확인 방법

[Ubuntu/Debian]
Step 1) 주요 경로에서 소유자·소유 그룹이 없는 파일 및 디렉터리 확인
```bash
# find /root /home /tmp /var/tmp /etc /usr/local -nouser -o -nogroup 2>/dev/null
```
Step 2) 불필요한 파일·디렉터리 제거 또는 소유자·그룹 변경
```bash
# chown <사용자> <파일경로>
# chgrp <그룹> <파일경로>
```
※ /proc, /sys, /dev, Ceph 등 가상 FS 경로는 제외

## U-20. /etc/(x)inetd.conf 파일 소유자 및 권한 설정

> **[Contrabass-Engine 환경 - 해당 안됨]**
> Contrabass-Engine에서 inetd/xinetd 서비스를 사용하지 않으므로 조치 불필요

### 점검 내용

/etc/(x)inetd.conf 파일 권한 적절성 여부 점검

### 조치 방법

/etc/(x)inetd.conf 파일 소유자 및 권한 변경 설정

## U-67. 로그 접근 통제

> **[Contrabass-Engine 환경 - 예외 처리 적용]**
> OpenStack 서비스 계정(nova, keystone, glance, neutron, barbican 등) 소유 로그 디렉터리는
> 해당 서비스가 직접 로그를 기록하는 구조로, root 소유 변경 시 서비스 장애 발생 가능.
> 서비스 계정 소유 + adm 그룹(권한 750) 구조로 접근 통제되어 other 접근 차단됨 — 실질적 보안 위험 낮음.
> root 소유 일반 로그 파일(/var/log/*.log 등)은 644 이하로 이미 양호.
> syslog/rsyslog 데몬 기록 파일(auth.log, kern.log, syslog 등)은 syslog:adm 소유로 정상 동작 구조.
> **→ 담당자 확인 후 예외 처리 적용 (조치 현황: 예외처리)**

### 점검 내용

로그에 대한 접근 통제 및 관리 여부 점검

### 조치 방법

디렉터리 내 로그 파일 소유자 및 권한 변경 설정

### 확인 방법

[Ubuntu/Debian]
Step 1) /var/log/ 소유자 및 권한 전체 확인
```bash
ls -la /var/log/
```
Step 2) root 소유 파일 권한 확인
```bash
find /var/log -maxdepth 1 -user root -type f -exec stat -c "%U %a %n" {} \;
```
Step 3) 서비스 계정 소유 디렉터리 확인
```bash
ls -la /var/log/ | grep -v '^d.*root'
```
양호 기준: 소유자=root(일반 로그), 권한=644 이하

Step 4) root 소유 일반 로그 파일 권한 조치 (644 이하로)
```bash
# chown root /var/log/<파일명>
# chmod 644 /var/log/<파일명>
```
※ 아래 항목은 소유자 변경 금지 (서비스 장애 위험)
- nova, keystone, glance, neutron, barbican, cinder, octavia, placement, manila 등 OpenStack 서비스 디렉터리
- auth.log, kern.log, syslog (syslog 데몬 기록)
- rabbitmq, mysql, pacemaker 등 미들웨어 디렉터리

※ 담당자 확인 후 예외 처리 적용
